# Flash Player (Chromium Extension) A lightweight, high-performance Chromium extension designed to parse and render Adobe Flash (`.swf`) assets using a custom WebAssembly pipeline, direct Canvas API rendering, and native extension request interception. --- ## Table of Contents - [Overview](#overview) - [Key Features](#key-features) - [Directory Structure](#directory-structure) - [Build and Installation](#build-and-installation) - [Prerequisites](#prerequisites) - [Building WebAssembly Components](#building-webassembly-components) - [Loading into Chromium](#loading-into-chromium) - [Architecture Overview](#architecture-overview) - [SWF Parsing & Decompression](#swf-parsing--decompression) - [Rendering Pipeline](#rendering-pipeline) - [ActionScript Execution Environment](#actionscript-execution-environment) - [Development Roadmap](#development-roadmap) - [License](#license) --- ## Overview The **Flash Player** extension enables modern Chromium-based browsers to intercept and render Legacy Flash files (`.swf`) without relying on NPAPI plugins or external third-party emulators. By combining Manifest V3 service workers, WebAssembly for binary parsing/decompression, and HTML5 Canvas for vector rendering, this project provides an independent, sandboxed runtime environment for SWF assets. --- ## Key Features - **Custom WebAssembly Engine**: Core parsing, Zlib/LZMA decompression, and vector tag extraction written in native C++ and compiled to WebAssembly for maximum performance. - **SWF Header Parsing**: Full support for identifying and extracting metadata from `FWS` (uncompressed), `CWS` (Zlib compressed), and `ZWS` (LZMA compressed) headers. - **Canvas Rendering Pipeline**: Translates SWF vector tags (`DefineShape`, `DefineShape2`, `PlaceObject`) into high-framerate HTML5 2D/WebGL rendering commands. - **ActionScript VM Stub**: Basic ActionScript Virtual Machine environment to handle frame navigation scripts, user inputs, and timeline control commands. - **Automatic Interception**: Uses Chromium's `declarativeNetRequest` and `webRequest` APIs to automatically route direct `.swf` URLs and embedded ``/`` tags to the local extension viewer. --- ## Directory Structure ```text flash-player-extension/ ├── manifest.json # Extension Manifest V3 configuration ├── background.js # Service worker handling network requests & interception ├── viewer.html # Main viewer interface container ├── viewer.js # Frontend bridge between Wasm core and Canvas ├── css/ │ └── viewer.css # Main styling for the viewer stage ├── icons/ │ ├── icon16.png │ ├── icon48.png │ └── icon128.png └── src/ # Core C++/WebAssembly Source Code ├── parser.cpp # Binary parser for SWF format ├── decompress.cpp # Zlib/LZMA decompression algorithms ├── avm_stub.cpp # Basic ActionScript interpreter stubs └── Makefile # Emscripten build rules ``` --- ## Build and Installation ### Prerequisites To compile the C++ core into WebAssembly, you must have the **Emscripten SDK (emsdk)** installed and available in your system path. - [Emscripten Installation Guide](https://emscripten.org/docs/getting_started/downloads.html) - Chromium-based browser (Google Chrome, Brave, Microsoft Edge, etc.) ### Building WebAssembly Components 1. Clone the repository: ```bash git clone https://github.com/your-username/flash-player.git cd flash-player ``` 2. Compile the C++ source files to WebAssembly: ```bash cd src make ``` *This generates `engine.wasm` and `engine.js` in the extension root directory.* ### Loading into Chromium 1. Open your Chromium-based browser and navigate to `chrome://extensions/`. 2. Enable **Developer mode** using the toggle switch in the top-right corner. 3. Click the **Load unpacked** button. 4. Select the `flash-player-extension` directory containing `manifest.json`. 5. The extension is now active. Any `.swf` file opened directly or embedded in a webpage will be processed by the extension. --- ## Architecture Overview ``` ┌────────────────┐ ┌─────────────────┐ ┌─────────────────┐ │ Intercepted │ ----> │ Background │ ----> │ Viewer Window │ │ SWF Request │ │ Service Worker │ │ (viewer.html) │ └────────────────┘ └─────────────────┘ └────────┬────────┘ │ ▼ ┌────────────────┐ ┌─────────────────┐ ┌─────────────────┐ │ HTML5 Canvas │ <---- │ Render Bridge │ <---- │ WebAssembly │ │ Output Buffer │ │ (viewer.js) │ │ Engine (C++) │ └────────────────┘ └─────────────────┘ └─────────────────┘ ``` ### SWF Parsing & Decompression 1. **Header Analysis**: Reads the first 8 bytes of the SWF file to inspect the signature bytes (`FWS`, `CWS`, or `ZWS`), Flash version, and total uncompressed file length. 2. **Decompression**: If a `CWS` signature is encountered, the payload starting at byte 8 is passed to the Zlib stream engine. For `ZWS`, an LZMA decompressor processes the payload. 3. **RECT Frame Extraction**: Reads variable-bit field structures (`RECT`) to determine the target frame dimensions and frame rate. ### Rendering Pipeline The engine translates SWF vector primitives into standard HTML5 Canvas instructions: - **Paths & Shapes**: Maps `StyleChangeRecord` and curve primitives (quadratic Bézier curves) directly to `canvasCtx.quadraticCurveTo()`. - **Fills & Color Data**: Evaluates solid, linear gradient, and radial gradient fill styles per display tag. - **Matrix Transformation**: Applies 2x3 display matrices to place, scale, rotate, and skew display objects frame-by-frame. ### ActionScript Execution Environment The lightweight VM handles stack-based bytecode evaluation: - Opcode parsing for `ActionPlay`, `ActionStop`, `ActionGoToFrame`, and `ActionGetURL`. - Maintains event-listener bindings for keyboard and mouse interactions (`MouseDown`, `KeyPress`). --- ## Development Roadmap - [x] Basic SWF header identification and binary buffer loading. - [x] Zlib payload decompression for `CWS` files. - [x] WebAssembly-to-Canvas rendering bridge for static shapes (`DefineShape`). - [ ] Complete implementation of quadratic curve drawing algorithms. - [ ] Advanced ActionScript 2.0/3.0 opcode coverage. - [ ] Audio stream decoding (MP3/Nellymoser tag handling). - [ ] WebGL rendering backend for high-resolution graphics acceleration. --- ## License This project is licensed under the MIT License.
